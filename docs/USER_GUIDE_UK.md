# Керівництво користувача

## 1. Перший запуск

1. Відкрийте застосунок у браузері.
2. Зареєструйтесь або увійдіть.
3. На головному екрані перейдіть до створення нової задачі.

## 2. Як створити просту задачу

1. Натисніть `Створити просту задачу`.
2. Введіть:
   - назву задачі
   - URL сторінки
   - тип рушія: `Статичний` або `Динамічний`
3. Перейдіть у вкладку `Селектори`.
4. Натисніть `Вибрати`, потім клікніть по елементу на сайті.
5. Додайте поля, які треба зберігати:
   - назва
   - ціна
   - посилання
   - зображення
6. Натисніть `Зберегти задачу`.

## 3. Коли який режим обирати

### Простий режим

Підходить, якщо вам потрібно:

- швидко зібрати каталог товарів
- спарсити список новин
- отримати базові дані без складних запитів

### Розширений режим

Потрібен, якщо ви використовуєте:

- кілька HTTP-запитів
- парсинг сторінок деталей
- webhook-сповіщення
- рекурсивний обхід
- складні JSON API

## 4. Як працюють основні вкладки

### Основне

- Назва задачі
- URL сторінки
- Метод `GET` або `POST`
- Тіло запиту для `POST`

### Селектори

- Селектор картки або рядка
- Поля для витягування
- Вибір елемента через візуальний селектор

### Пагінація

Використовуйте, якщо дані розбиті на кілька сторінок.

Доступні режими:

- кнопка `Наступна`
- шаблон URL з `{page}`
- нескінченний скрол

### Розклад

Дозволяє запускати задачу автоматично:

- щогодини
- щодня
- у будні
- за власним cron-виразом

### Деталі

Потрібно, якщо треба перейти з картки в окрему сторінку товару або статті та витягнути додаткові поля.

### Додатково

Тут зібрані технічні параметри:

- timeout
- retries
- anti-bot
- проксі
- webhook
- рекурсивний обхід

## 5. Робота з результатами

У розділі `Результати` можна:

- переглядати зібрані записи
- шукати по тексту
- бачити зміни між запусками
- експортувати дані

Формати експорту:

- JSON
- CSV
- Excel
- TXT, якщо ця функція доступна для вашої задачі

## 6. Робота з проксі

У розділі `Проксі` можна:

- додавати нові проксі
- імпортувати списком
- перевіряти доступність
- використовувати ротацію

Використовуйте проксі, якщо сайт блокує часті запити або має обмеження по IP.

### VPN (WireGuard і OpenVPN)

VPN працює як ще один проксі: тунель піднімається лише для парсера, мережа сервера, SSH і сайт не змінюються.

1. `Проксі` → **«+ VPN»**, виберіть вкладку **WireGuard** або **OpenVPN**.
2. Вкажіть назву (напр. «Нідерланди») і вставте вміст файлу:
   - WireGuard — `.conf` (секції `[Interface]` з `PrivateKey`, `Address` і `[Peer]` з `PublicKey`, `Endpoint`);
   - OpenVPN — `.ovpn` із вбудованими сертифікатами (`<ca>`, `<cert>`, `<key>`). Логін і пароль потрібні,
     лише якщо в `.ovpn` є `auth-user-pass`.

   Якщо вставити файл не в ту вкладку, тип перемкнеться сам.
3. За кілька секунд (OpenVPN — до хвилини) у рядку VPN з'явиться статус: **«тунель працює»** і вихідний
   IP/країна, або **«помилка тунелю»** з причиною.

#### Безкоштовні сервери VPN Gate

`Проксі` → **«Імпорт VPN Gate»** → виберіть країну → **«Імпортувати»**. Сервіс збирає список OpenVPN-серверів
VPN Gate (`*.opengw.net`) з каталогу vpnhub.me, завантажує їхні `.ovpn` з vpngate.net і додає кожен як VPN.
Для України це близько 170 серверів, імпорт триває 1–2 хвилини.

- Одразу вмикаються лише перші N серверів (поле «Одразу увімкнути», за замовчуванням 5), решта додається
  вимкненими — вмикайте потрібні кнопкою **▶**. Одночасно працює не більше 10 OpenVPN-тунелів
  (кожен — окремий процес на сервері); зайві отримують статус помилки з поясненням.
- Сервери VPN Gate тримають волонтери: вони часто зникають і змінюють порти. Повторний імпорт оновлює
  конфіги вже доданих серверів і додає нові, дублів не створює.
- Волонтер, який тримає сервер, технічно бачить трафік. Не використовуйте ці VPN для задач з логінами
  й паролями до сайтів.

Кнопки в рядку VPN:

- **✓** — перевірка: вихідний IP, країна, час відповіді;
- **Сайт** — перевірка на конкретному сайті (напр. `https://zapchasty.com.ua/`): один запит через VPN
  і один напряму з сервера, видно код відповіді, час, заголовок сторінки і чи сайт блокує;
- **✎** — змінити назву або замінити конфіг (збережений конфіг не показується — там приватний ключ);
- **⏸ / ▶** — вимкнути / увімкнути тунель;
- **✕** — видалити.

У задачі: `Додатково` → **«Використовувати проксі / VPN»** і виберіть:

- «Ротація: усі робочі проксі й VPN» / «лише проксі» / «лише VPN»;
- або конкретний VPN — тоді всі запити задачі йдуть лише через нього.

«Видалити неробочі» VPN не видаляє — тільки звичайні проксі.

Для адміністратора: тунелі тримає окремий процес pm2 `vpn` (`src/vpn/vpn.daemon.js`) і кладе конфіги
в `~/.parser-vpn` (права 600).

- WireGuard — запускає `~/bin/wireproxy` (або `WIREPROXY_BIN`), root не потрібен.
- OpenVPN — запускає `sudo -n openvpn` (або `OPENVPN_BIN`; `VPN_SUDO=0`, якщо демон уже root). Потрібні
  пакет `openvpn` (`sudo apt-get install -y openvpn`) і sudo без пароля. Тунель запускається з `route-nopull`:
  маршрути сервера не змінюються, а скрипт `~/.parser-vpn/ovpn-route.sh` додає окрему таблицю маршрутизації
  й правило `ip rule from <IP тунелю>`. У тунель іде лише трафік локального SOCKS5 цього VPN
  (`127.0.0.1:<порт>`). Ліміт одночасних OpenVPN-тунелів задає `VPN_MAX_OPENVPN` (за замовчуванням 10).
- З `.ovpn` береться лише білий список директив: `up`, `script-security`, `plugin`, `route`, шляхи до файлів
  тощо відкидаються, бо openvpn працює від root.
- Сервер спільний, тому тунелі не зачіпають інших користувачів: головна таблиця маршрутизації не змінюється
  (маршрут до підмережі тунелю переноситься в таблицю тунелю), iptables не використовується, DNS сервера
  не змінюється. Локальний SOCKS тунелю приймає з'єднання лише від процесів користувача парсера та root.
- На OpenVZ доступ до TUN вмикає хостинг. Вузол `/dev/net/tun` демон відтворює сам, якщо той зник після
  перезавантаження.

Після першого деплою: `pm2 start ecosystem.config.js --only vpn && pm2 save`. Після оновлення коду:
`pm2 restart vpn app parser.worker`.

## 7. Типові сценарії

### Каталог товарів

- рушій: `Статичний`
- контейнер: `.product-card`
- поля: `title`, `price`, `image`, `link`

### Новини

- рушій: `Статичний`
- контейнер: `article`
- поля: `title`, `date`, `summary`, `link`

### JS-сайт

- рушій: `Динамічний`
- дочекайтесь повного рендеру сторінки через Puppeteer

### Оновлення кількості (або іншого поля) через пошукові підказки сайту

Коли сайт не показує потрібне значення у списку товарів, але віддає його в JSON (наприклад,
підказки пошуку), поле можна донаповнювати окремим запитом на кожен товар.

Приклад — `zapchasty.com.ua`, поле «Кількість»:

1. У редакторі задачі додайте звичайні поля списку: `Назва`, `Артикул`, `Ціна`, `Посилання на товар`.
2. Додайте поле `Кількість`, тип **«лінк на іншу сторінку»**, і увімкніть
   «Перейти за посиланням та зібрати дані зі сторінки».
3. У **URL шаблон** вкажіть запит до пошуку, підставивши значення з товару через `{{поле}}`.
   Кілька URL розділяються `||` — вони пробуються по черзі, доки не знайдеться потрібний товар:
   ```
   https://zapchasty.com.ua/poshuk?limit=10&ajaxSearch=1&id_lang=2&q={{Артикул}} || https://zapchasty.com.ua/poshuk?limit=10&ajaxSearch=1&id_lang=2&q={{Назва}}
   ```
   Значення `{{…}}` підставляються в URL закодованими (пробіли, `&`, `#`, `*` у назвах не заважають).
4. У блоці «Витяг полів з JSON-відповіді» натисніть **«+ вибір за збігом»**. З'явиться шлях
   ```
   [product_link={{Посилання на товар}}].quantity
   ```
   Він означає: у JSON-масиві відповіді знайти запис, у якого `product_link` дорівнює полю
   «Посилання на товар» нашого запису, і взяти з нього `quantity`.
   Колонку залиште порожньою — тоді значення запишеться в саме поле `Кількість`
   (історія змін і експорт працюють як раніше). Якщо вказати колонку, значення піде у `Кількість_колонка`.
5. Увімкніть **«Відстежувати зміни»** для поля `Кількість`.
6. За потреби натисніть **«+ дата перевірки»** — з'явиться правило `[…].@now` з колонкою `оновлено`:
   у `Кількість_оновлено` записується дата й час (за Києвом), коли товар знайдено в пошуку.

#### Конструктор пошуку

Щойно в полі є правило «вибір за збігом», під URL шаблоном з'являється **Конструктор пошуку**:

- **Адреса пошуку** — URL з `{q}` на місці запиту,
  напр. `https://zapchasty.com.ua/poshuk?limit=10&ajaxSearch=1&id_lang=2&q={q}`.
- **Запити** — список, пробуються по черзі (стрілки ↑↓ міняють порядок). Для кожного обирається:
  - поле товару (`Артикул`, `Назва`, …);
  - «після символу» — взяти частину після першого входження символу (`.` для `01.00188222` → `00188222`);
  - «перші N символів» або «перші N слів».

Конструктор сам записує URL шаблон, напр. `…q={{Артикул}} || …q={{Назва|words:3}}`. Ці ж фільтри можна
писати вручну: `{{Поле|after:X}}`, `{{Поле|chars:N}}`, `{{Поле|words:N}}` (можна поєднувати через `|`).

#### Як економляться запити

Кожна відповідь пошуку (до 10 товарів) запам'ятовується до кінця запуску. Для наступного товару
спочатку перевіряється, чи він уже прийшов у попередніх відповідях, — якщо так, запит не робиться.
У «Історії запусків» видно: `пошук: N запит. · з кешу M · не знайдено K`.

Вимір на категорії «підшипники» (191 товар): повний артикул — 72 запити (решта з кешу),
перші 4–6 символів артикула — 115–117 запитів (короткий запит повертає більше «чужих» товарів).
Тому першим запитом краще ставити повний артикул, а назву — запасним.

Правила та обмеження:

- Збіг шукається серед усіх записів відповіді (для цього сайту — до 10). Порівнюйте за унікальним
  полем (посилання, id): артикул у різних товарів може повторюватися.
- Якщо збігу немає в жодному з URL, у записі лишається значення зі списку (зазвичай порожнє).
- Запити йдуть строго по одному, без паралельних пачок (щоб не навантажувати сайт). Пауза після
  кожного реального запиту — **`followDelay`** (мс, за замовчуванням 1000 мс, з випадковим розкидом
  до ×2); товари, взяті з кешу, паузи не потребують. Основна «Затримка» (`delay`) тут не використовується.
- Запит виконується статичним рушієм, антибот-заголовки застосовуються за налаштуваннями задачі.
- Ціну можна оновлювати так само: додайте друге правило `[product_link={{Посилання на товар}}].price`
  з колонкою (наприклад, `price_api`) або окреме follow-поле.
- Перевірити відповідь джерела можна запитом `POST /api/tasks/preview` з `options.jsonPath = "."`.

## 8. Поради для нетехнічного користувача

- Починайте з простого режиму.
- Не додавайте всі опції одразу.
- Спочатку перевірте 2-3 поля на одній сторінці.
- Якщо дані не знаходяться, спробуйте інший контейнер елемента.
- Якщо сайт динамічний, перемкніть рушій на `Динамічний`.

## 9. Якщо щось не працює

- Перевірте, чи відкривається URL у браузері.
- Переконайтесь, що селектор вказує саме на повторюваний елемент.
- Для `POST` перевірте формат тіла запиту.
- Для великих сайтів збільшіть timeout.
- Якщо сайт блокує запити, увімкніть anti-bot або проксі.
