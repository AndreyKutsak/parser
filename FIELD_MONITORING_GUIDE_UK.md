# Керування фічею моніторингу змін полів

## Що це таке?

Фіча **моніторингу змін полів** дозволяє відстежувати, як змінюються конкретні значення полів під час кожного лансування парсера. Система автоматично порівнює нові значення з попередніми результатами і записує:

- 📊 **Старе значення** (яким воно було раніше)
- 📊 **Нове значення** (яким воно стало зараз)
- ⏰ **Коли змінилось** (дата і час)
- 🏷️ **Яке поле змінилось** (назва поля)

---

## Як активувати моніторинг для полів?

### Крок 1: Відкрийте конфігурацію задачі

1. Перейдіть у **"Мої задачі"** або **"Огляд"**
2. Знайдіть задачу, для якої хочете включити моніторинг змін
3. Клацніть **"Редагувати"** або по задачі, щоб відкрити модальне вікно

### Крок 2: Увійдіть у розділ "Селектори"

У вікні редагування задачі знайдіть **"Селектори"** → **"Список полів"**

Тут ви побачите усі поля, які вилучаються:

- `name` - назва товару
- `price` - ціна
- `link` - посилання
- `description` - опис
- тощо...

### Крок 3: Позначте поля для моніторингу

Поруч з кожним полем буде **checkbox** або **перемикач**:

```
☑ name        - назва товару
☑ price       - ціна
☐ link        - посилання
☐ description - опис
```

**Клацніть на checkbox** для всіх полів, які хочете відстежувати.

### Крок 4: Збережіть задачу

Натисніть кнопку **"Зберегти"** або **"Оновити задачу"**.

## Де побачити моніторені зміни?

### 1️⃣ **При експорті в JSON**

Кожен результат матиме новий об'єкт `_fieldChanges`:

```json
{
  "_url": "https://example.com/page1",
  "name": "Товар ABC",
  "price": "$34.99",
  "link": "https://example.com/product/123",
  "_fieldChanges": [
    {
      "field": "price",
      "oldValue": "$29.99",
      "newValue": "$34.99",
      "changedAt": "2026-04-12T14:30:00Z"
    },
    {
      "field": "name",
      "oldValue": "Товар A",
      "newValue": "Товар ABC",
      "changedAt": "2026-04-12T14:30:00Z"
    }
  ]
}
```

### 2️⃣ **При експорті в CSV**

Додатковий стовпець `_fieldChanges` з форматованим текстом:

| \_url                     | name      | price  | \_fieldChanges                                                                              |
| ------------------------- | --------- | ------ | ------------------------------------------------------------------------------------------- |
| https://example.com/page1 | Товар ABC | $34.99 | `price: $29.99 → $34.99 [12.04.2026, 14:30]; name: Товар A → Товар ABC [12.04.2026, 14:30]` |

### 3️⃣ **При експорті в Excel**

Ві отримаєте **3 листи**:

#### **Лист 1: "Результати"** (результати з останніми даними)

- Усі звичайні стовпці результатів
- **Новий стовпець `_fieldChanges`** з усіма змінами для кожного результату

#### **Лист 2: "Історія підзадач"** (якщо є підзадачі)

- Історія всіх запусків підзадач
- Включає также обвід `_fieldChanges` для кожного запуску

#### **Лист 3: "Зміни полів"** ⭐ **НОВИЙ**

- **Один рядок для кожної зміни поля**
- Стовпці:
  - `_url` - яке посилання
  - `_detailUrl` - для підзадач
  - `_fieldName` - яке поле змінилось
  - `_oldValue` - що було раніше
  - `_newValue` - що стало зараз
  - `_changedAt` - коли це сталось

**Приклад листа "Зміни полів":**

| \_url                     | \_fieldName | \_oldValue | \_newValue | \_changedAt       |
| ------------------------- | ----------- | ---------- | ---------- | ----------------- |
| https://example.com/page1 | price       | $29.99     | $34.99     | 12.04.2026, 14:30 |
| https://example.com/page1 | name        | Товар A    | Товар ABC  | 12.04.2026, 14:30 |
| https://example.com/page2 | price       | $49.99     | $45.99     | 12.04.2026, 14:35 |

## Практичні приклади використання

### 📌 Приклад 1: Моніторинг змін цін

**Перевіримо, чи змінилась ціна товару:**

1. Відкрийте задачу парсування каталогу товарів
2. Позначите **"price"** для моніторингу
3. Запустіть парсер
4. Експортуйте в Excel
5. Поглядіть на **Лист "Зміни полів"** - там будуть усі товари, ціни яких змінилися

### 📌 Приклад 2: Відслідковування оновлень назв товарів

**Знайдіть товари, які були перейменовані:**

1. Активуйте моніторинг **"name"** і **"description"**
2. Запустіть парсер двічі з інтервалом в кілька днів
3. При експорті отримаєте список усіх змін у назвах та описах

**CSV буде виглядати так:**

```
_url,name,_fieldChanges
https://example.com/p1,"Товар XYZ","name: Товар XYZ Pro → Товар XYZ Max [12.04.2026, 10:00]"
https://example.com/p2,"Опис","description: Стара опис → Нова опис [12.04.2026, 11:15]"
```

### 📌 Приклад 3: Аналітика змін для звітності

**Створіть звіт про активність на сайті:**

1. Активуйте моніторинг для всіх важливих полів: `price`, `status`, `quantity`, `availability`
2. Налаштуйте **відносити парсер** (наприклад, щодня о 10:00)
3. Кожен день експортуйте дані в Excel
4. Используйте лист **"Зміни полів"** для:
   - Побудови графіків змін цін
   - Виявлення найчастіше змінюваних товарів
   - Аналізу часу, коли відбуваються оновлення

## Важливі моменти

### ✅ Що отримаєте

- **Повна історія змін** - зберігається дата, час, старе і нове значення
- **Экспорт в 3 форматах** - JSON, CSV и Excel
- **Автоматичне порівняння** - система сама порівнює попередні результати
- **Зручна аналітика** - лист "Зміни полів" в Excel со всіма змінами в одному місці

### ⚠️ Що потрібно знати

- **Моніторинг працює при порівнянні результатів**: система дивиться на **результат з попереднього запуска** парсера. Якщо це перший запуск для цієї сторінки - немає з чим порівнювати, тому змін не буде відзначено.

- **Укв для URL з підзадачами**: якщо у вас есть підзадачи (детальні сторінки) - зміни також відстежуватимуться для них

- **Будь-які типи значень**: моніторинг працює з текстом, числами, масивами та об'єктами

- **Для правильної загрузки**: використовуйте однакові селектори при кожному запуску - це гарантує що значення будуть коректно порівняні

## Запуск експорту з моніторованими змінами

### Через REST API

Експортуйте результати як завжди - зміни автоматично включатимуться:

```bash
# Експорт в JSON
GET /api/tasks/:taskId/export/json?runId=...

# Експорт в CSV
GET /api/tasks/:taskId/export/csv?runId=...

# Експорт в Excel
GET /api/tasks/:taskId/export/excel?runId=...
```

Усі файли будуть містити інформацію про моніторовані зміни полів.

### Через веб-інтерфейс

1. Перейдіть на **"Результати"** вашої задачі
2. Натисніть кнопку **"Експорт"**
3. Виберіть формат (JSON, CSV, Excel)
4. Завантажте файл - він автоматично включатиме зміни

## FAQ

**P: Чи втратяться попередні результати, якщо я активую моніторинг?**
О: Ні, все попередні результати залишаються. Моніторинг просто додасть нову інформацію для майбутніх запусків.

**P: Чи можна деактивувати моніторинг для полів?**
О: Так, просто знімите позначку с checkbox для поля в конфігурації задачи і збережіть.

**P: Скільки часу зберігатимуться зміни?**
О: Нескінченно - доки існує результат у базі даних.

**P: Що робити, якщо значення не порівнюються правильно?**
О: Переконайтеся, що:

1. Селектори однакові в обох запусках (при редагуванні - вони оновлюються для нових запусків)
2. Поле зберігається в обох результатах
3. Увага на типи даних (текст, число, масив - мають бути однакового типу)

**P: Чи підтримується моніторинг вложених полів?**
О: Наразі - отримуються значення на верхньому рівні object `data`. Вложені поля можуть порівнюватись, але як цілі об'єкти.
